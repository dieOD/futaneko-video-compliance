# FutaNeko iOS動画部品のソース・差し替え資料

FutaNekoで使用する動画部品の対応ソース、変更内容、再構築方法、利用者自身の署名で動画部品を差し替えるための資料を提供します。

FutaNekoはLGPL 2.1以降の [FFmpeg](https://ffmpeg.org/)、mpv、libplaceboと、そのほかのオープンソース部品を使用しています。対応ソースと各ライセンス全文は下記のリリースから取得できます。本体の画面・投稿・NG等のソースコードを公開するリポジトリではありません。

対応ソースや原典通知に残る `NijiNeko` は旧開発名です。`nijineko_*` という内部識別子も旧開発名として保持しており、本体ソースの公開範囲や追加の利用許諾を示すものではありません。

## ダウンロード

使用しているアプリの「バージョンとビルド番号」に対応する行から、ソースと再リンク材料の両方を取得してください。

| 1.0.0 (1) | 配布済みTestFlight版。MP4変換追加前 | [ビルド1の資料一式](https://github.com/dieOD/futaneko-video-compliance/releases/tag/ios-1.0.0-1) |
| 1.0.0 (2) | MP4変換を含む未提出候補の記録（固定済みスナップショット） | [ビルド2の資料一式](https://github.com/dieOD/futaneko-video-compliance/releases/tag/ios-1.0.0-2) |
| 1.0.0 (3) | 初回ストア提出版の記録。MP4／MOV判定修正とアプリ内の利用条件・資料案内を含む | [ビルド3の資料一式](https://github.com/dieOD/futaneko-video-compliance/releases/tag/ios-1.0.0-3) |
| 1.0.0 (4) | 再審査用ビルド。サムネイル初期OFF・初期NG・NG巻き込み修正を含む | [ビルド4の資料一式](https://github.com/dieOD/futaneko-video-compliance/releases/tag/ios-1.0.0-4) |

Build 2の資料は、固定済みIPAから作成した当時のスナップショットです。現在のアプリソースに加わった後続の変更（動画MIME検証の修正を含む）は含みません。App Store提出済み・承認済み・最新版であることを示す資料ではありません。

Build 3は別のIPAに対応する新しい資料です。動画ネイティブ部品はBuild 2と同じ構成で、本体側の後続修正を含む再リンク材料を提供します。初回公開版のFutafuta連携と内部検証機能は無効です。Build 1・2の固定資料は上書きしていません。

Build 4は再審査用の別IPAに対応する資料です。動画ネイティブ部品はBuild 3と同じ構成で、本体側にサムネイル初期OFF・初期NG・NG巻き込み修正を含みます。利用者は設定からサムネイル表示をON/OFFできます。Futafuta連携・内部検証機能は無効を維持し、Build 1・2・3の固定資料は上書きしていません。

資料の公開は、そのアプリがApp Storeで一般公開済みであることや、Appleの審査承認を意味しません。

各リリースには次を置いています。

- `*-video-sources.tar.gz`: 固定原本8件、改修パッチ・追加コード、ビルド手順、原典ライセンス全文。
- `*-relink.tar.gz`: 本体ソースを含まない未暗号化アプリコピーと、改変した動画部品への差し替え・再署名用ツール。
- `release-manifest.json`: アプリと各アーカイブの対応、SHA-256、照合方法。

再リンクキット内の `base-application/Runner.app` は、元のコード署名情報を保持した未暗号化の再署名用素材です。プロファイルを含めないため単体では署名検証・インストールの対象ではなく、`replace_and_sign.py` で利用者自身の証明書と開発用プロファイルを使った新しいコピーを作る前提です。

Git上の `source/` は、手順・追加コード・差分・ライセンスの閲覧用です。上流アーカイブと再リンク用アプリはGitの履歴に入れていません。再構築する場合は、リリース欄から完全なキットを取得してください。

## 再構築・差し替え

macOS、Xcode、Python 3.10以降、必要なビルドツールが必要です。キットを展開し、まず `python3 -B verify.py` で同梱ファイルを確認してください。外側のアーカイブのSHA-256もリリース欄のmanifestと照合してください。

ソースキットの `README.ja.md` に、3アーキテクチャの再構築と、自分で確認した追加パッチの適用方法を記載しています。再リンクキットの `README.ja.md` に、実機用 `Mpv.framework` の差し替え方法を記載しています。

再署名には利用者自身の証明書・開発用プロファイル・別のBundle Identifierを使います。配布者の秘密鍵やプロファイルは含みません。ツールは新規コピーだけを作成し、端末へのインストール、既存アプリの削除、保存データの消去は行いません。

元のアプリコピーには署名証明書の公開情報や、ビルド時のファイル名・パスの参照文字列が残ります。これは本体ソースや秘密鍵とは異なります。App Store版のDRMを解除する手順は含みません。
